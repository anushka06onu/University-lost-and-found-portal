# Authentication and frontend repair

No fallback records, fake sessions, client OTP bypass, or simulated uploads remain. API failures are shown explicitly. Accounts use BCrypt; historical SHA-256 accounts upgrade only after a valid login. Existing sessions without an expiry are invalidated. New sessions last 12 hours and logout/password changes revoke them. Registration refuses existing accounts instead of overwriting passwords. Email OTPs are delivered through configured SMTP, never returned to the browser or logged; codes expire and have separate registration/reset purposes and a five-attempt limit per stored code. Default administrator and report seeding is removed.

Public item responses omit contact details and author email. Only the report author or administrator can see contact information in authenticated item detail. No automated ownership-verification or claimant messaging workflow is implemented. Do not put private contact information in public descriptions. Image links require HTTPS on res.cloudinary.com; file upload is explicitly unavailable until implemented.

Before deployment: configure real SMTP and disable app.mail.mock-mode, configure a persistent database, remove previously seeded sample/admin accounts after reviewing live records, and resolve duplicate email rows before the unique constraint is applied. Pending unverified accounts can request a reset then verify only through a new registration flow; an administrator may need to remove a stale unverified record. A Vercel static deployment does not run the Java backend: set APP_CONFIG.API_BASE_URL to a separately hosted backend and configure permitted CORS origins. No hosting credentials are available in this environment. Tests run in GitHub Actions because Java/Maven are unavailable locally.
